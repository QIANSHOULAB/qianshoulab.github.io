# 二房东算账 · 设计记录（0.4.2）

0.4.2 起改名：中文「二房东算账」，英文「Rent Splitter」（以前叫包租僧 / Baozu · Rent Splitter），挪进总舵「小工具」。网址、文件夹 `baozuseng`、本机存储键、备份里的 `app` 名都没换。

给接手的人看。`index.html` 管全部逻辑和样式；**界面上所有的字在 `strings.js`**（中文、英文各一套）。同目录还有两份 manifest（中文 `manifest.webmanifest`、英文 `manifest.en.webmanifest`，都由 `bench/strings-export.js` 从 `strings.js` 生成）、`sw.js`、`icon.svg`（favicon，跟总舵首页卡片同图形同色）和从它出的四张 PNG（`bench/icons.js` 重出）。

## 结构

- `strings.js`：`{ zh: {...}, en: {...} }`，两套键一一对应、函数参数一样（`bench/strings-export.js` 会核对）。日期格式（`fm`）、标点（`sep / c / end`）、示例账本的名字（`demo`）、支出快捷钮、房间快捷钮也在这里。浏览器里挂到 `window.BZS_STR`，Node 里 `require` 得到同一个对象（bench 脚本按它找按钮上的字）。
- `index.html`：样式 + 一段 IIFE 脚本（`<script src="strings.js?v=版本">` 在它前面）。脚本顺序：
  1. 挑语言：默认英文，第二语言中文（Song 11-03 22:19）；`UI.lang`（右上角选过）优先，不看浏览器语言；`T = STR[语言]`。`applyLang()` 同时换 `<html lang>`、`<title>`、description、主屏名字、manifest 链接。`index.html` 里写死的 `<html lang>` / `<title>` / description / manifest 是英文（没跑脚本前、爬虫看到的），`bench/strings-export.js` 会核对它跟 `strings.js` 一致。
  2. `MODEL-START … MODEL-END`：纯函数，不碰 DOM：`span / calc / parseRoster / makeDemo`。
  3. 状态与存储（`S`、`St`、`UI`），`Ops`（所有改账的入口）。
  4. 撤销（`snap`/`undoable`：改账前存一份，提示条给「撤销」）；备份 / 导回（也能整页丢文件），结清后提示存备份。
  5. 视图：首页、单套房、总账；底部弹出的表单（sheet）。
  6. 事件、路由（`#h-xxx` 进房子，`#ledger` 总账）。
- `window.__bzs` 只暴露纯函数给测试用，不暴露数据。
- `sw.js`：先上网拿新版，没网用上次缓存的外壳。只缓存页面文件，账不在缓存里。
- `bench/`：比武材料（场景、独立答案、真流程脚本 `run-baozuseng.js`（第三个参数 `en` 跑英文界面，名字名单用 `scenario-en.json`）、步骤账 `steps.js`、测快 `speed.js`、撤销检查 `undo-check.js`、中英排版检查和截图 `shots-0.4.js` → `shots-0.4/`、文字导出 `strings-export.js` → `strings-0.4/`、提意见核对 `feedback-check.js` → `results/feedback-0.4.2.json` + `shots-0.4.2/`、结果）。`steps / speed / undo-check` 固定 zh-CN。

## 数据

一个账本 = `{ houses: {id: house}, order: [id] }`，存 `localStorage['baozuseng.v1']`（键名沿用 0.1，字段只增不改，0.1 的账直接能读）。

```
house  { id, estate, unit, self, byRoom, created:'YYYY-MM', demo?,
         tenants:[person],            // 花名册：没碰过的月份照它生成
         fixed:[{id,name,amt}],       // 每月固定支出
         months:{ 'YYYY-MM': month } }
person { id, name, room, rent, share, from?, to? }   // from/to 'YYYY-MM-DD'，空=不限
month  { elec, self, rows:[person + {paid, owe?}], exp:[{id,name,amt,fixed}] }
```

- **旧月冻结**：一改账，`freeze()` 把开张月到本月都实体化，之后改本月不会带歪旧月；改本月的房租/名字同时改花名册，下个月跟着走。
- **住的日期是人的属性，不是某个月的**：改入住/住到，`place()` 会对所有已实体化的月份重排——住着的补上（新人只补到当月及以后，有入住日的按入住日往前补），不住的拿掉，日期同步。
- 界面小状态 `localStorage['baozuseng.ui']`：`a2hs`（主屏引导关了）、`asked`（哪个月提示过备份）、`lastBk`（上次备份日）。

## 算法（全部整数分）

- 天数 `span(x, m)`：入住日、住到那天**都算**；当月天数 D。
- 房租：住满 = 月租；否则 `round(月租分 × 天数 ÷ D)`。
- 电费按「人天」平摊：总人天 = 各房客当月天数之和 + 二房东自住时 + D。
  分摊的人付 `round(电费分 × 他的天数 ÷ 总人天)`。包电的人那份、二房东自己那份、凑整的零头都归二房东（`eatC`）。
  所有人住满时等于老算法 `电费 ÷ 人头`，0.1 的旧账数不变。
- 一间两人：按人算，各写各的月租，电费各算一个人头。按房间看时显示这一间合计。
- 收入 = Σ(房租 + 电费)；支出 = 电费账单 + 其他支出；净赚 = 收入 − 支出。
- 欠租：本月标欠 `owe`，以后各月显示「之前欠」，点「还清了」清掉。
- `Math.round` 是 .5 进位；分子分母都是小整数，浮点不会把 .4999 算成 .5（比武 151 处核对 0 差）。
- 名单粘贴能认 `11号入住`、`住到20号`、`20号搬走`，日期落在当前看的月份。

## 存储与不丢账

数据不出这台设备，没有服务器，没有账号。

1. **放到主屏幕**：第一次在手机上打开就有一张一行的卡片（空账本时在按钮下面，有账时在标题下面），不关也不挡事。iPhone 教「分享 → 添加到主屏幕」（放上主屏的网页 iOS 不会 7 天清数据）；安卓有安装事件就直接一个按钮。关掉就不再出现；已在主屏打开不出现。
2. **持久存储**：有了自己的账就调 `navigator.storage.persist()`；结果显示在页脚（「已上锁」或「记得存备份」）。
3. **备份**：每月所有房子都收齐、电费填了，弹一次「存备份」（每月只弹一次，示例账本不算）。手机上走分享面板（iPhone 选「存储到文件」），电脑上直接下载 `二房东算账备份-日期.json` / `rent-splitter-backup-日期.json`（0.4.2 前叫 `包租僧备份-日期.json` / `baozu-backup-日期.json`）。备份里 `app: 'baozuseng'` 不换：导回只看文件内容、不看文件名，旧名字的备份照样导回，新备份旧版也认。首页「账本」组里随时能存，超过 31 天没存会标黄。
4. **导回**：首页或空账本点「导回备份」→ 选文件，或者把文件丢进页面任何地方。这台没账就直接导入；有账也直接换，提示条给「撤销」（0.3.0 起不问「确定吗」）。
5. Google 网盘多机同步：按拍板，等 Song 要了再做，代码没写。

## 0.3.0 去掉的步骤（怎么做的）

- **全屋账单一条**：`billsAll(h, c, m)` 出一条消息——抬头、电费怎么分（有人按天折才提）、每人一行「名字 应交（住几天，房租 + 电费 + 之前欠，已收）」。电费按钮下面就是主按钮「复制账单」。单人账单还在房客浮层里。
- **都收了**：没收的 ≥ 2 位时，房客列表里出一行「都收了」，`Ops.allPaid` 只动「没收、也没标欠」的人；提示条给撤销。
- **建房 + 贴名单一张单子**：`rosterEditor()` 是贴名单的公共件（新建房子浮层和「粘贴名单」浮层都用），认出来的人列成卡片当场改；点「建好」前没跑完的解析先跑掉，用户改过的卡片不会被重解析冲掉。
- **单套房直接进**：启动时只有一套自己的房（没有示例），路由直接进那套房（`history.replaceState`），左上角「房子」回总览。
- **不问「确定吗」**：删房子、删房客、删支出、清示例、导回换账，一律先做，`undoable(msg, snap())` 提示条 6 秒内能撤。
- **电费打错**：框下一句人话，分摊和「复制账单」先藏起来、上面的数变淡，不让拿错数发账单。

## 中英两套（0.4.0，0.4.1 改成默认英文）

- 0.4.1 起默认英文、第二语言中文，不跟浏览器语言走（0.4.0 是跟浏览器走、切换在页脚）。每页右上角一个「EN / 中文」分段控件（`langSeg()`，在顶栏 `#navR` 最右边），选了记在 `localStorage['baozuseng.ui'].lang`（读写都包了 try/catch，存不了也照样切，只是下次回到英文）。bench 里中文那几遍先往 localStorage 写 `lang: zh`，等于「选过中文」的人。
- 英文是照英文用户习惯重写的，不是翻译：名字 0.4.2 起就叫 **Rent Splitter**（以前 Baozu · Rent Splitter，空状态大标题两色；现在一行），副标题「Power bill, split to the cent. Drama not included.」；梗用干冷、轻描淡写（Did the owner forget to collect? / Empty rooms collect dust, not rent. / We’ll do the long division.；0.4.2 去掉了 Email the abbot），不硬翻贫僧、施主。用词照新加坡、马来西亚合租的叫法（Master room / Common room / Rent to owner / Wi-Fi），电费叫 power。发给租客的账单（全屋一条、单人一条）也是英文写法（Hi Ming, for August it’s …）。
- 英文日期跟浏览器的英文地区走（en-US：Aug 5；en-GB、en-SG：5 Aug），总账柱状图下面是月份首字母。
- 英文名单也能贴：`incl.` / `power incl.` / `all-in` 算包电，`not incl.` / `excl.` 算分摊；`from 11th`、`moves in Nov 20`、`until 15th`、`moving out 28 Nov` 认成入住、住到；`$1,200/month`、`SGD 480 pm` 认月租。中文名单的识别一处没动（0.3.0 的样例逐条对过，结果一样；顺手让「900/月」也能认）。
- 按钮上不写句子：贴名单时「还有 1 位没写名字或月租」从按钮挪到名单上方那一行（红字），按钮只写「建好 / Add」。
- 中文词不拆行：副标题、空状态那句加了 `word-break:keep-all`，只在标点处断（以前手机上「多少」被拆成两行）。英文副标题用不换行空格，手机上在句号处断。
- 顶栏（滚动后）和底部提示条的底色 0.4.1 起 98% 不透明：浅色白 `rgba(255,255,255,.98)`、深色 `rgba(28,28,30,.98)`，保留 `saturate(180%) blur(20px)`，跟知客僧、戒尺僧一致（0.4.0 是 72%，滚过去的字会透出来）。提示条随之改成浅底深字、「撤销」用主色，加一圈细线。
- 两份 manifest 由 `bench/strings-export.js` 从 `strings.js` 生成；脚本同时导出 `bench/strings-0.4/zh.txt`、`en.txt`（一行一条），并检查 `index.html` 里写死的中文 `<title>` / description（脚本没跑之前、爬虫看到的）跟 `strings.js` 一致。

## 提意见（0.4.2）

- 放哪：页脚一行「要新花样、嫌哪里反人类？**提意见**」/「Feature idea or a gripe? **Feedback**」。没有设置页；空账本那屏就是介绍页，跟首页、房子页是同一个 `footer()`，所以介绍页和产品界面各一个、都在最不打扰的地方。总账页没页脚，没加。
- 怎么开：`<a class="fb" href="mailto:…">`，点了就是系统自己的邮件程序，不接表单、不收数据、不发信。收件人 `FB_TO` 在 `index.html` 拼起来写（少招垃圾邮件）；标题 `T.fbSubject(VERSION)`（「[千手院反馈] 二房东算账 0.4.2」/「[QIANSHOU feedback] Rent Splitter 0.4.2」）；正文 `T.fbBody` 三行提示，中间空行留着写，最后一行 `版本 · 系统 · 浏览器`。标题、正文都过 `encodeURIComponent`。
- 设备简写 `deviceTag()`：从 UA 认系统（iOS / iPadOS 带大版本、Android 带大版本、Windows、macOS、ChromeOS、Linux）和浏览器大版本（微信、Edge、Opera、三星、Firefox、Chrome、Safari）；Chromium 把 Windows 10 / 11、macOS、Android 的版本冻在 UA 里，有 `navigator.userAgentData` 就再问一次 `platformVersion`（Windows 13 起是 11；macOS 10.x 写到 10.15），问到了把页脚链接重填。点的那一下（document 的 click）也按当前语言、设备重填一遍再放行，切了语言不用刷新。
- 样式：页脚 12 号字里一个主色、600 字重的链接；`padding:12px 8px; margin:-12px -4px` 让点的地方 ≥ 44 高又不把行撑高；只在有鼠标的设备上悬停加下划线（手机点完不留下划线）。
- 核对：`bench/feedback-check.js`（要 `LANG=C.UTF-8`，不然沙盒里 Chromium 读不了中文文件名，旧名字备份导不回——是沙盒的事）。中英各在介绍页、首页、房子页点，电脑首页点，中文切 EN 再点，再换 Edge、微信、Mac、Win11 的 UA 点，一共 14 下；在 window 冒泡阶段记下 href、拦住跳转，对收件人、标题、正文、最后一行，网址里不许有没编码的字；顺带导回 `包租僧备份-*.json`、`baozu-backup-*.json`，再存一份看新文件名。

## 改字、改版本

- 改字：只改 `strings.js`，然后 `node bench/strings-export.js`（重出 manifest 和文字清单）。加新键要中英两套都加，函数参数一样。

## 已知边界

- 「删掉这条」只删当月这行，删本月时连花名册一起删。
- 改过去月份的人加日期，会把他补进以后各月（这是设计：人是连续住的）。
- 只在 Chromium 里真跑过；iPhone Safari 的分享面板存文件、主屏模式没在真机上试。
- 提意见只核对了 mailto 链接本身；真机上点了会不会拉起邮件 App（iPhone 没装邮件 App、微信里打开）没在真机上试。
- 英文也只在 Chromium（en-US）里真跑过；英文 iPhone 上的日期选择器、分享面板、「Add to Home Screen」字样没在真机上对过。
- 示例账本按打开时的语言生成；先在中文里点了示例再切英文，示例里的名字还是中文（自己的账本来就不翻）。
