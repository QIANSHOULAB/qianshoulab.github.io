# 译经僧 · 设计记录（给接手的 Claude）

网址：https://qianshoulab.github.io/yijing/ 　版本：0.4.0（四轮：中英两套文字，2026-11-03；0.3.0、0.2.1、0.2.0、0.1.0 同日）
英文名：Yijing · Data Mover　英文副标题：Data migration, minus the suffering.

## 干什么
把 A 系统导出的文件（CSV / TSV / XLSX / JSON）翻成 B 系统导入模板的格式。只做文件翻译，不连系统。全在浏览器本地跑。

## 结构
- `index.html`：CSS + 全部 JS。
- `strings.js`（0.4.0 起）：页面上给人看的字全在这，`window.YJ_STR = { zh, en }` 两套：标题、meta description、介绍、按钮、提示、吐司、出错、模板名（`tpl`、`tplOrder`）、示例数据（`demoData`，中英各一份「旧系统导出」）。index.html 里 `<script src="strings.js?v=版本">`，换版本记得改 `?v=`，免得缓存里新旧对不上。加字两套都加，`node bench/strings040.js` 会对键、导出 `bench/strings-0.4/zh.txt`、`en.txt`。
  - 挑语言（`pickLang`，Song 11-03 22:19 定的规矩：默认英文，第二语言中文，不跟浏览器语言）：网址 `?lang=zh|en` > 右上角切换记下的 localStorage `yijing.lang.v1` > 英文。页面静态的 `<html lang>`、`<title>`、meta description 也写英文（不跑 JS 的爬虫、链接预览看到的就是英文）。`STR` 是 `let`，`setLang()` 换掉它，`applyLang()` 改 `<html lang>`、`<title>`、meta description、顶栏（含 EN / 中文 分段控件 `#navLang`）、拖放层，再 `render()`；载着示例就换成那门语言的示例，别的（文件、对法、改过的列）原样留着。
  - 顶栏右边是「配方」+ EN / 中文。手机上配方只留图标和个数（`aria-label` 有字），滚动后居中的小标题不放，不然英文「‹ Qianshou Lab」会被挤成两行。
  - 存进状态里的字不存成句子：列旁边那句小字 `m.note` 存键（`'noteGuess'`，带参数的存 `['noteRule', a, b]`），渲染时 `noteTxt()` 出字；读不动 `S.err = {name, why}`，`errTxt()` 出字；工作表数存 `src.sheets`。这样切语言不用重算。
  - 内置模板的名字跟语言走：`tgtName(t)` 有 `STR.tpl[t.id]` 就用它，用户自己的模板用文件名。配方「同一个目标」对内置模板认 id、对自己的模板认名字。
  - 英文版 `:root:lang(en)` 把西文字体排到中文字体前面（不然 Windows 上英文用雅黑的西文字形）。英文首屏大标题是 `Yijing` + 灰一档的 `· Data Mover`，手机上大白话那半截自己一行。
- `icon.svg`（favicon，图形同总舵首页卡片）、`apple-touch-icon.png`（180 满版主屏图标，`bench/icon.js` 从 icon.svg 出）。
- `lib/xlsx.full.min.js`：SheetJS 0.18.5（npm 包原样拷贝，Apache-2.0，见 `lib/xlsx.LICENSE`），只在读写 Excel 时懒加载。
- JS 分区（按 index.html 里的注释块）：
  - 概念词典 `C`：每个概念一组列名同义词（中英），带目标类型 t。`VS`：选项值同义词（男/女→M/F、在售→active、资产→Asset、借/贷…）。
  - 内置模板 `TPL`：8 个（CRM 英文、客户名单中文、Shopify 常用列、网店中文、会计科目中/英、WooCommerce 商品、HubSpot 联系人）。列可带 c（指定概念）、alt（备选概念，88 分）、t（类型，含 list 多值）、v（选项）、fmt、dec、unit（g/kg…）、sep（多值拼接符）、req。
  - `NULLV`：表示「没有」的值（未知/不详/N/A…），目标是选项列时换成空。`CCN`：国家名 → 电话国家码；`NLEN`：国家码 → 本地号码位数（验货用）。
  - `PROFILES`：认得出的来源系统（Shopify、WooCommerce），按列名集合判断；alias 改列义（Shopify 的 Type → 分类，Product Category 不用）。来源卡片上显示「Shopify 导出」。
  - 读文件 `readFile`：编码自动（UTF-8 失败退 GB18030，认 BOM/UTF-16），分隔符嗅探，跳过表头上方的标题行，JSON 自动找数组并把嵌套对象拍平成 `a.b`。
  - 转换 `compile(map, targetCol)`：把一列的配置编成 `row => string`，出错置全局 `BAD`。之后按目标类型验货（邮箱、选项值、必填）。
  - 自动对列 `autoMap`：来源列概念走 `srcConcepts`（带来源系统改义）。评分——规整后同名 100；同概念且同义词完全一样 92（对上）；列名里含同义词 72（存疑）；bigram 模糊 ≥60（存疑）；列名不像但内容像（邮箱/电话/日期）58（存疑）。贪心一对一。选项列没对上时 `enumCover` 看值：某来源列 ≥90% 的值能换成目标选项（至少两种），就对上（可以和别的目标列共用一个来源列，标存疑）。另有特例：拆姓名（First/Last ← 姓名）、合姓名、Shopify Handle 借货号。
  - 状态 `S`：src / rows / tgt / maps / fmt / recipe / bad / tidy / prep。改动走 `changed()` → `prep()`（整理行）→ `rebuild()`（重编函数）→ `render()` → `scan()`（全表扫错，60ms 防抖）。
  - 整理 `prep()`：`S.src.rows` 是原始行，`S.rows` 是整理后的行，预览、扫错、导出都用它；抽样、值统计用原始行。(1) 目标首列必填并且只来自一个来源列时，这一列为空的行跳过。(2) `detectGroup` 在剩下的行里找分组列：每格都有值、同值连成一段、重复 ≥10%。每组首行 ≥90% 有值、组内后续行 ≤10% 有值的列，在组内往下补。如果主键列本身也在要补的列里，就不跳行，改在全量行上重新检测。`S.tidy` 是用户开关：fill / drop 管自动的两项，fillOn 按列名单独开关某一列（列弹层里的「空格照抄上一行」）。检测结果按「文件名 | 主键列 | 行数」缓存。
    - 0.2.1 起认打乱的分组：先照旧找「同值连成一段」的列；找不到时，在「同值不挨着」的候选列里找（前 2000 行粗筛掉每组平均超过 20 行的列，比如国家、性别），要补的列条件改成「≥90% 的组有值、多出来的值 ≤ 非首行的 10%、组内有两种值的组 ≤2%」。认出后 `S.prep.g.shuf = true`：整理时按组收行（按分组列第一次出现的顺序，组内保持原顺序），组里空格用本组前面最近的值，前面没有就用本组第一个值（只从不会被跳过的行取值，免得 Shopify 图片行的图冒充主图）。顺手整理卡片上那行变成「同一个「Handle」排回一起，空格补齐」，同一个开关管。
  - 换值 pair：`[原值, 目标]`。目标是字符串时 '' 表示保持原样；null 表示换成空；`{by, pre, v, els}` 表示看 by 列（存列名）是否以 pre 里的任一前缀开头，是就换成 v，否则换成 els。`autoPairs` 遇到一个值能换成多个选项时，不自动选；只有会计的「损益」在有科目代码列时生成条件（`ambigRule`）。
  - 多值列（op list）：`splitList(v, sp)`。有 | , ; 、 换行 tab 就只按它们拆，片段里的空格保留（多词标签不拆）。没有这些分隔符时看空格：中文格子照旧按空格拆；英文格子看 `listPlan(列)`（整列抽 3000 格算一次，按列号+文件缓存）——
    - 多词标签 phr：别的格子里用强分隔符分开、自带空格的片段；或者相邻两词 a b 满足「a 只出现在 b 前面、b 只出现在 a 后面、≥2 次」或「≥5 次且一边总是贴着另一边」，连成链（back to school）。
    - auto（整列是不是空格分隔）：先按 phr 粘好，再数出现 ≥2 次的单元里「前后邻居都换过 ≥2 种」的自由单元，≥2 个且占一半以上就算。
    - auto 不成立时逐格兜底：粘好后每个单元都在本列别处单独出现过（known）才拆，比如 `linen cotton`；`Gift Ideas` 这种就不拆。
    - op.space：缺省 = 按上面自动判断；true = 中英文都按空格拆（仍粘多词标签）；false = 都不按空格拆。列弹层里是「按空格拆」开关，下面一句说粘住了哪些词。
- 配方：localStorage `yijing.recipes.v1`，列按「列名」存，不按序号。0.3.0 起没有「存配方」按钮：每次下载 `remember()` 自动记（同一份表头 + 同一个目标只留一个，新记的吐司里「不记」能撤）。丢新文件时用列名集合 Jaccard ≥0.6 且配方用到的列都在，就自动套，吐司「重新对」撤回。
- 上回的目标格式：localStorage `yijing.last.v1` = {tgt, fmt}，选模板、换格式、下载时写；开页面就用它。
- 0.3.0 流程（`render()` 按 `view()` 分三屏）：empty（没来源：大标题 + 丢文件卡 + 目标单子/上回的目标）→ pick（有来源没目标：来源卡 + 目标单子）→ work（两头卡 + 瞄一眼 + 顺手整理 + 对列 + 预览 + 底栏）。
  - 存疑 `isDoubt(i)`：conf 是 guess / req，或全表有译不动的格子；`S.ack` 是点过「对」的列。
  - 自动下载：`S.auto` 在丢文件 / 换目标时置上，`scan()` 扫完若不是示例、存疑为 0 就 `doExport(true)`。最后一处点「对」（`ackOne`）、底栏「都对，下载」、改完存疑列关上弹层（`closeSheet`）那一下也出文件。
  - 两个文件一起丢 / 一起选（`loadFiles`）：行少的当目标模板。读不动的文件（扩展名不是表格、或没表）错误写在丢文件那块（`S.err`），不弹窗。
- 每列 map：`{src:[列序号], cnst:null|固定值, op:{t:...}, conf:'sure'|'guess'|'blank'|'req'|'user', note}`。
- op 类型：none / date(from,to) / name(part) / join(sep,smart) / phone(cc,by,auto,style) / num(dec,thou,unit) / map(pairs) / list(sep) / case(mode)。phone.by 存国家列的列名，逐行查 `CCN`，查不到就用 cc；auto 表示没有国家可看时按号码长相判断（11 位 1 开头 → 86，8 位 [3689] 开头 → 65）。num.unit 存目标单位，来源带的单位按 `UNIT` 换算；不认识的单位置 BAD。配方会存 tidy。

## 踩过的坑
- Playwright 无头 Chromium 下，`a.download` 文件名含非 ASCII（中文、→）时 `suggestedFilename()` 变成 `download`。真浏览器正常，没改；测试别拿这个当失败。
- 同义词「含在里面」只对中文 ≥2 字、英文 ≥4 字生效，不然「名」会吃掉「姓名」「公司名称」。`name`/`title`/`type`/`code` 这种多义词故意不进词典，只靠完全同名或模板里的 c 指定。
- 日期 a/b/yyyy 分不清日月时默认按 月/日/年 并标「存疑」。
- CSV 导出固定加 UTF-8 BOM（Excel 打开中文不乱码）。拍板 1 定的是带 BOM。
- 「Tan Wei Ming」这类新马华人英文名，拆姓名会按西方规矩把最后一个词当姓。

- 数字解析先走 `PLAIN` 快速路径（纯数字和千分位）；电话按国家查码时用 Map 记住结果。不做这两步，10 万行要慢 0.4 秒。
- 「拆了再拼」0.2.0 只有中文按空格拆；0.2.1 起英文看整列判断（见上面多值列），只出现一次的多词标签在空格分隔的列里认不出来，会被拆开。
- 0.4.0 起页面默认英文、不看浏览器语言；测试要中文就网址带 `?lang=zh`，或者点 `#navLang [data-l="zh"]`（记在 localStorage，同一个浏览器上下文里重开还是中文）。
- 本机测试别用 8765 端口：沙盒里别的会话可能占着同一端口、服务的是另一份仓库。`run_ours.js`、`shots.js`、`e2e021.js` 认 `YJ_URL`，`or_run.py` 认 `OR_URL`。

## 还没做
按条件换值只支持「看某列开头」，不支持正则和多条件；不能在目标模板里加列、改列名；没有「一行拆多行」（多行并一行的方向，往下补和跳行已经做了）；没有 Web Worker（10 万行内不卡，100 万行没测）；Zapier、Make 没比；自动下载（非人手点）在 iPhone Safari 上放不放行没真机试过。英文版没让英文母语的人读过；中文版的 <title>、meta description 靠 JS 换（不跑 JS 的爬虫、链接预览只看到英文那份）；Windows 上英文字体（Segoe UI）没真机看过。
