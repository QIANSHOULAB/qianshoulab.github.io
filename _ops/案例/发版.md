# 案例：发版（推上去就自己发，Song 只点更新）

## iPhone app（一叶笺，免费 Apple ID）
- 推上 main → GitHub Actions（macos-26、Xcode 26）编译、单测、模拟器截图；`ios/project.yml` 里的版本号没发过，就出未签名的 .ipa，建 Release `ios-v<版本>`，再改 `ios/sidestore.json`（SideStore 源）。Song 在手机 SideStore 里下拉刷新、点 UPDATE，SideStore 用他的 Apple ID 签名装上。（qianye `.github/workflows/ios.yml`，Song 11-21 拍板）
- 打 tag 之前先空跑一遍出包那几步（`ios-probe.yml`），出包挂了把错误原样贴出来。
- 免费账号的墙：同时只能装 3 个（扩展也算一个；现在 SideStore、一叶笺、陪玩截屏占满），7 天要重签一次（SideStore 自己续）。要第 4 个就等开发者账号，或者放进 LiveContainer。
- 版本号每次 +0.0.1；两张单前后脚发，后发的接着前一个号（108 发成 0.7.4，因为 0.7.3 被 105 用了）。

## 第 4 个以后的 iPhone app：住进 LiveContainer（还没跑通，先写下路线）
- 免费账号 3 个名额被 SideStore、一叶笺、陪玩截屏占满。换成「LiveContainer + SideStore」后它自己占 1 个，里面能装不限个数的 app。
- 自动进去的路：发版流水线照一叶笺那套出 .ipa，再写进一个「千手院总源」（跟 `ios/sidestore.json` 同一种格式，所有新 app 一个源）。Song 在 LiveContainer 的 Sources 里加一次这个源（`livecontainer://source?url=<源的网址>` 一点就加），新 app 出现在列表里，点 Install。
- 更新：LiveContainer 文档没说会自己提醒更新。我们的 app 自己查 GitHub 上有没有新版，有就弹一下，点了用 `livecontainer://install?url=<ipa 网址>` 交给 LiveContainer 装。重装数据会不会丢，第一个 app 上线时先试。
- 住进去的 app 不能带扩展（小组件、分享、截屏那种），也用不了推送、Siri、iCloud 这些付费账号才有的权限。所以一叶笺留在原生名额，新 app 要想住进去，就设计成不带扩展、不靠 iCloud 的。

## Windows 程序（知客僧、戒尺僧、录入僧）
- 推上去 → `windows-latest` 打 exe → 冒烟测试（在临时目录当家跑一遍）→ 传到固定的 Release（比如 `zhike-latest`），带 `version.json` 和中英两套更新说明。（总舵 `.github/workflows/zhike.yml`）
- 程序自己更新：Song 自己的电脑全自动；别人的只提醒有新版、写这版干了啥，点了才更新，也能自己打开自动更新。

## 网页
- 总舵 qianshoulab.github.io 从 main 根目录发 GitHub Pages：推上 main 就是上线，每个工具一个文件夹。
- 新仓库的网页（Song 的 GitHub）：建公开仓库 → 单文件 `index.html` 推 main → 开 Pages → 打开验证 → 把网址发给他（`gua-github` 技能）。施工队建公开仓库会被拦，聊天这边先建空仓库。

## 发完
- 回话里直接给最新的网址、ipa 地址或 exe 地址，不等 Song 问。
