# 案例：发版（推上去就自己发，Song 只点更新）

## iPhone app（一叶笺，免费 Apple ID）
- 推上 main → GitHub Actions（macos-26、Xcode 26）编译、单测、模拟器截图；`ios/project.yml` 里的版本号没发过，就出未签名的 .ipa，建 Release `ios-v<版本>`，再改 `ios/sidestore.json`（SideStore 源）。Song 在手机 SideStore 里下拉刷新、点 UPDATE，SideStore 用他的 Apple ID 签名装上。（qianye `.github/workflows/ios.yml`，Song 11-21 拍板）
- 打 tag 之前先空跑一遍出包那几步（`ios-probe.yml`），出包挂了把错误原样贴出来。
- 免费账号的墙：同时只能装 3 个（扩展也算一个；现在 SideStore、一叶笺、陪玩截屏占满），7 天要重签一次（SideStore 自己续）。要第 4 个就等开发者账号，或者放进 LiveContainer。
- 版本号每次 +0.0.1；两张单前后脚发，后发的接着前一个号（108 发成 0.7.4，因为 0.7.3 被 105 用了）。

## 第 4 个以后的 iPhone app：住进 LiveContainer（铁屑江湖第一个走，Song 还没装成）
- 免费账号 3 个名额被 SideStore、一叶笺、陪玩截屏占满。换成「LiveContainer + SideStore」后它自己占 1 个，里面能装不限个数的 app。
- 出包（铁屑江湖 120，总舵 `.github/workflows/tiexie-ios.yml`）：照一叶笺那套，macos-26 上 XcodeGen → 编译 → 单测 → 模拟器截图 → 版本号没发过就出未签名 .ipa，建 Release `<app>-v<版本>`，再改「千手院总源」：总舵根目录 `apps.json`，https://qianshoulab.github.io/apps.json ，跟一叶笺 `ios/sidestore.json` 同一种格式（AltStore 源），所有住进 LiveContainer 的 app 都往这一个源里加。
  - 只在 app 自己的文件夹和工作流变了才跑；`concurrency` 一趟一趟来、不取消在跑的；截图平时只当工作流附件，只在发版那下跟 `apps.json` 一起提交一次，带 `[skip ci]`；推之前 `pull --rebase`，推不上再拉再推，最多 5 次（一叶笺 0.7.8 两趟撞车死在截图提交那步）。
  - 坑：施工队的 GitHub 令牌没有 workflow 权限，推不了 `.github/workflows/*.yml`。新建、改工作流要聊天那边推（120 卡过一次，17:29 代挪）。
- 装（每个新 app 只一次）：LiveContainer 本体 Sources → + → 粘贴 `https://qianshoulab.github.io/apps.json` → Add（加过就不用再加）→ 点 app → Install → 回 My Apps 打开。
- 坑：LiveContainer 里正跑着别的 app（比如开着内置 SideStore）时，`livecontainer://install` 只弹 “Please restart LiveContainer to install apps.”，不装（LiveContainer 3.8.14 `TweakLoader/UIKit+GuestHooks.m` 的 `install` 分支；Song 11-24 20:00 撞上）。先回本体再装：
  - Safari 打开 `livecontainer://livecontainer-launch?bundle-name=ui` → Open → “switch to LiveContainer?” 点 OK：回本体主屏，同时关掉「开机直接进 SideStore」的标记 `LCOpenSideStore`。
  - 再开安装链接；或者本体 Apps → 左上 + → Install from URL → 贴 https 的 ipa 地址。
  - iPhone Settings › Apps › LiveContainer › Open SideStore 开着的话，每次冷启动都进 SideStore，装东西前都得先走上面这步。
  - 本体和 SideStore 都有叫 “My Apps” 的页，认底下几格：本体四格（Sources / Apps / Tweaks / Settings），SideStore 五格（News / Sources / Browse / My Apps / Settings）。
- 更新：LiveContainer 不会自己提醒。我们的 app 打开时读 `apps.json`，有新版就在设置图标上点个小红点，设置里一行「有新版 0.x.y，点一下更新」。点了先把要寄的寄掉，再开 `livecontainer://livecontainer-launch?bundle-name=ui` 回本体，小字提示 Sources → 千手院 → 点 app → Install，弹 Installation 时选替换那项（不选 Install as New）。
  - 别从 app 里直接开 `livecontainer://install`：app 住在 LiveContainer 里面跑，链接回到 LiveContainer 自己手上，正跑着 app 就只弹 “Please restart LiveContainer”（上面那个坑，自己撞自己）。铁屑江湖 0.1.0、0.2.0 就这么写的，0.2.1 改掉。`bundle-name=ui` 后面带 `open-url` 也没用，本体回主屏不接着办。
- 数据：住进去的 app 数据在 LiveContainer 给它的数据文件夹里，更新只换包，照设计不丢；Song 第一次更新时验。
- 住进去的 app 不能带扩展（小组件、分享、截屏那种），也用不了推送、Siri、iCloud 这些付费账号才有的权限。所以一叶笺留在原生名额，新 app 要想住进去，就设计成不带扩展、不靠 iCloud 的。

## Windows 程序（知客僧、戒尺僧、录入僧）
- 推上去 → `windows-latest` 打 exe → 冒烟测试（在临时目录当家跑一遍）→ 传到固定的 Release（比如 `zhike-latest`），带 `version.json` 和中英两套更新说明。（总舵 `.github/workflows/zhike.yml`）
- 程序自己更新：Song 自己的电脑全自动；别人的只提醒有新版、写这版干了啥，点了才更新，也能自己打开自动更新。

## 网页
- 总舵 qianshoulab.github.io 从 main 根目录发 GitHub Pages：推上 main 就是上线，每个工具一个文件夹。
- 新仓库的网页（Song 的 GitHub）：建公开仓库 → 单文件 `index.html` 推 main → 开 Pages → 打开验证 → 把网址发给他（`gua-github` 技能）。施工队建公开仓库会被拦，聊天这边先建空仓库。

## 发完
- 报告、回话里写「已发」之前，先看 Release 里真有那个包（`gh api repos/<owner>/<repo>/releases/tags/<tag>`）；CI 还在跑就写「在出包」。166 报告写了「0.3.7 已发，CI 全绿」，其实那趟挂在单测、重跑还在截图，Song 11-26 11:21 去找没找到。
- 住进 LiveContainer 的 app（铁屑江湖），「Song 试」第一步写「app 设置红点 → 点更新 → LiveContainer Sources → 千手院 → Install 选替换」，不写 SideStore（166 报告照抄一叶笺写错过）。
- 回话里直接给最新的网址、ipa 地址或 exe 地址，不等 Song 问。
