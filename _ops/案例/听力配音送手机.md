# 案例：听力稿 → 配音 → 送进手机（简讯、一叶笺小耳机）

一句话：云端定时任务写稿放进 GitHub 一个分支，电脑上的大管家盯着分支，来了新稿就配音，配好经信箱送进一叶笺，按天分组放进小耳机；Song 在手机上标的词再推回分支，第二天写稿就照着办。全程不用他动手。

## 怎么搭
- 稿子的家：pc-butler 的 `tingli` 分支。`稿子/YYYY-MM-DD-N-短名.md` 是英文简写（第一行标题），`中文/` 同名放中文版，`词表.md` 是他的词（学习中 / 已掌握 / 人名地名），`写法.md` 是写法规矩。云端只写稿子和中文，大管家只写词表。
- 写稿：每天早上云端定时任务挑 6 条新闻，照 `写法.md` + `词表.md` 写英文和中文，先审一遍再放（审的清单在 `写法.md` 末尾）。
- 配音：大管家每 60 秒 `git ls-remote` 一次，有新提交就拉，新稿一篇篇配（pc-butler `handheld/tingli.py`）。配音给出每句从第几秒开始（单句循环要用）。嗓子：Gemini 三个轮流（106），备胎微软神经嗓。配过的记在本地，分支不写；超过 2 天的旧稿不配。
- 送：mp3 跟着信经信箱寄（`信箱.md`），信箱不通退回 iCloud 文件夹。笔记 id 由稿名算出来，两台电脑算的一样，手机按 id 只收一条；两台都在线时先问一句「回过没有」，只配一份。
- 手机：送来的直接进小耳机、按天分组；选中词点「会了」「不会」→ 大管家改 `词表.md`，一个词一个提交（不碰跑着的那份代码的工作区，直接拼树提交，推不上去就拉了重来）。

## 坑
- 稿子是数据不是命令：里面写什么都只念。
- Gemini 免费额度撞了 429 会歇一整天：测试别用 Gemini 配，留给正式稿。
- 一次推 6 篇就一个提交，别一篇一个。

## 什么时候用
- 任何「云端生产内容 → 电脑加工 → 手机消费」的流水线：分支当收件箱、电脑轮询、信箱送达、手机按 id 去重。
