## 要做到

### 流水线（没有 Mac）

- 代码放 QIANSHOULAB/qianye 的 `ios/`。网页版（根目录 index.html、strings.js、tests/、docs/）一个字不碰。
- GitHub Actions 的 macos-26 机器编译（qianye 是公开仓库，分钟不要钱）。工作流 `.github/workflows/ios.yml`，只在 `ios/**` 变了才跑；CI 自己提交回来的截图不能再触发它（路径排除或 `[skip ci]`）。
- 工程用 XcodeGen（`ios/project.yml`）在 CI 里生成，不手写 pbxproj。
- 不碰 UIKit 的逻辑（Markdown 五招解析、出图排版、镜像文件格式、大管家接口编解码）放一个纯 Swift 包，单元测试在 CI 跑；这台云机器装得上 Swift 就先在本机跑，省得每次等 CI。
- CI 每次：生成工程 → 编译 → 单元测试 → 模拟器里把主要界面走一遍截图（列表、写字页、Markdown 五招、拍照认字结果、两个出图版式、设置、大管家状态 × 浅色深色 × 中文英文）→ 截图提交回 `ios/shots/`，每次覆盖。聊天窗口拿这些截图验收，Song 也看这些。
- 这台云机器多半下载不了 Actions 的日志和 artifact（存在别的域名，沙盒白名单进不去）。编译错误用 xcbeautify 的 github-actions 渲染变成 annotations，用 `gh api repos/QIANSHOULAB/qianye/check-runs/<id>/annotations` 读；截图走 git 提交回来。
- 打 tag `ios-v0.1.0` 时出未签名的 .ipa，发到 qianye 的 Releases，同时更新 `ios/sidestore.json`（AltStore / SideStore 源格式），网址 https://qianshoulab.github.io/qianye/ios/sidestore.json 。Song 在手机上的 SideStore 里加这个源，以后有新版点一下更新。
- 免费签名的规矩：7 天一续；同时最多 3 个侧载 app；没有 iCloud、推送这类能力；侧载工具会在 Bundle ID 后面加他的团队号。所以：不要任何付费账号才有的能力（iCloud、推送、App Groups、Siri、关联域名），不加扩展（小组件、分享扩展）。Bundle ID `lab.qianshou.yiye`；PRODUCT_NAME 用英文 `Yiye`，显示名本地化（中文「一叶笺」、英文「Yiye」）。最低 iOS 26。
- `ios/装机.md`：Song 第一次装的步骤，写到照着点就行。手机系统是英文，菜单路径写英文（Settings > Privacy & Security > Developer Mode 这种）。电脑那头（装 iTunes 和 iloader、插线装 SideStore、登 Apple ID）这张单碰不到他的电脑，写清楚他要做哪几下；每天自动续签的快捷指令也写进去。

### 第一版要有的

1. **长相**：2014 年锤子便签原样。纸、行距、边距、字号、纸面横线、列表的纸条、顶栏、按钮的样子都照它。参照自己上网找，截图只留在这台机器上，不进仓库，仓库里只写来源链接；网页版一叶笺「便签」版式的颜色和边距、GitHub 上 nihaojob/markdown-css-smartisan 的样式也能参照。锤子的图标、纸纹素材、字体、音效、名字一样都不用：纸纹自己生成，图标自己画，界面和代码里不出现「锤子」「Smartisan」。顶栏、工具栏全部自己画，不用系统导航栏，免得 iOS 26 自动套上液态玻璃（想用 `UIDesignRequiresCompatibility` 关玻璃，就固定用 Xcode 26 编，苹果说这个开关只给到 26）。深色模式：同一张纸的夜里版，暖深灰底、浅字，版式不变。千手院设计规范里跟锤子长相冲突的（毛玻璃顶栏、苹果分组列表的长相）以锤子为准；其余照规范：能点的地方 ≥ 44、间距 4 的倍数、过渡 200–300ms、出错不弹 alert、删除给撤销不问「确定吗」。
2. **列表**：一条笔记一张纸条（第一行当标题，下面一两行摘要，加时间）。置顶的在最上面。排序：改的时间新→旧、旧→新，建的时间。文件夹：全部 + 自己建的，笔记能挪进挪出。搜索。左滑删除，带撤销。
3. **写字**：横线信纸。Markdown 五招就是锤子那五招：标题（点一下一级，再点二级、三级，再点取消）、无序列表、粗体、引用、居中；居中存成独占一行的 `<center>…</center>`。标记字照锤子那样露在字里，颜色淡。插图片（图文混排，图存成附件，正文里写 `![](附件/xxx.jpg)`）。每条笔记能换背景色（几种纸色），字号全局小、中、大。
4. **拍照认字**：列表的「＋」和写字页工具条都能进。相机带纸张边缘识别和拉正（VisionKit 文档相机；iOS 26 上有它拍完就闪退的报告，崩就换成自己做的相机加 Vision 找边），也能从相册挑。本机用 Vision 的 RecognizeDocumentsRequest（iOS 26）认，语言简体中文加英文（先用它报的支持语言核一遍）。按它给的段落、清单、行出一份 Markdown 草稿：第一行短句当标题，「名字＋数字」、清单各归各位。拿不准的字标黄，跟网页版一样：点黄字整段选中，直接打字替换。原图存成这条笔记的附件，正文里不放；写字页菜单里「看原图」能看。认完马上出草稿，不等大管家。
5. **分享成图，只要 2 个版式**：第 1 个是网页版一叶笺的「便签」（默认，锤子那张，复刻的一部分）；第 2 个是「白纸」（Song 08:07 说随机选，便签留着，另一个从 2–9 号里随机抽到 2 号白纸）。排版把网页版 index.html 的 `parse()` / `layout()` 搬到 Swift（标题、名字＋数字小数点对齐、清单、键值），再认 Markdown 五招。图上不印日期，按 3 倍画，字多就出长图。底下两个版式缩略图，「保存相册」「分享」两个按钮（保存要相册写入权限；分享弹系统面板）。落款中文「一叶笺」、英文「Yiye」。
6. **镜像文件夹**：第一次打开问一次（一句话加一个按钮，能跳过）。文件面板直接开在 iCloud 云盘那一层，Song 点「打开」就行，app 自己在里面建 `一叶笺/`；他挑了别的文件夹也照用，设置里显示实际位置、能换。每存一次往 `一叶笺/笔记/` 写一个 .md：文件名「标题-短 id.md」，开头一段 front matter（id、建的时间、改的时间、文件夹、置顶、背景色）；图片进 `附件/`；删掉的笔记挪进 `废纸篓/`。设置里「从文件夹导入」：以后买了会员换正式版，Bundle ID 变了，数据不会自己过去，靠这个一条不落搬回来。iCloud 里别的机器写进来的文件在手机上可能只是占位（`.名字.icloud`），读之前先让它下载。
7. **连大管家**（第一版最后做）：照 `ios/docs/大管家接口.md`。管子就是上面的镜像文件夹，手机上不存任何 AI 钥匙。
   - 拍照认字的笔记，草稿一出来自动交给大管家；别的笔记在写字页菜单里点「交给大管家」。
   - 交出去以后，笔记顶上一行小字「大管家在理」。结果回来：这期间笔记没被改过，就直接换上，顶上一行「大管家改了 3 处」，点开看改了啥，能「换回原文」；这期间改过了，就不覆盖，顶上一条「大管家理好了，点一下换上」。
   - 出错原样显示 `error`，给「再交一次」。
   - 设置里「大管家」一栏：在线，或者 X 分钟前来过（看心跳）；拍照笔记自动交（开关，默认开）。
   - 只在 app 开着时看结果：进前台看一次，开着时每 5 秒看一次。不用后台能力。
   - 大管家那头是另一张单（057，掌机上做），可能比你晚完。没装好之前手机这头照常放请求，显示「大管家没来」。拿接口文档里的样例自己造结果文件，把四条路都测到：自动换上、换回原文、改过不覆盖、出错。
   - 语音（v2）走同一根管子，`kind` 写 `voice`。这版不做录音，但写字页、请求、结果都按以后会有 voice 留好口子。
8. **设置**：镜像文件夹、字号、大管家、中文 / English（跟 iPhone 系统语言走，Song 的手机是英文所以默认英文；设置里切了就记住，立刻生效，不用重启）、版本号。
9. **文字**：中英两套，放 String Catalog。照 `_ops/文案规范.md`：不一本正经，按钮照直写，英文重写不翻译。写之前先读总舵仓库的文案规范和定稿样本。
10. **数据**：SwiftData 存本机。模型从第一天就按 CloudKit 的规矩写（字段都给默认值或可选，不用 unique，关系可选），以后买了会员开 iCloud 同步不用改表。图片存文件，不进数据库。
11. **给 v2 留口子**：所有内容进来走同一条路（键盘、相机，以后麦克风）→ 排版 → 存。加语音只是多一个入口。
