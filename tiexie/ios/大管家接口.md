## 信箱、信封、加密、收发

全照一叶笺 `ios/docs/大管家接口.md`（QIANSHOULAB/qianye）的 v2、v3，一个字不改：

- 地址 `https://luruseng-relay.lunzigeju.workers.dev/dgj/<box>/…`，信封 `{v:2, kind, id, at, data, files}`。
- AES-256-GCM，AAD `yiye-dgj/2/<box>/<to>`（前缀照旧写 `yiye-dgj`，跟一叶笺同一套代码），寄出去的字节 `nonce(12) ‖ 密文 ‖ tag(16)`。
- 手机 `ws?as=phone`，大管家 `ws?as=pc&who=desk`。
- 用一个新的信箱号，跟一叶笺各走各的；不开新路径前缀。
- 这个信箱只有电脑连，掌机不连。

手机这头（app 0.1.0）：

- app 在前台、配过对就连 `ws?as=phone`，每 30 秒发 `{"t":"state"}`；退到后台就断。
- 连上先办 `hello` 里攒着的回信，再寄发件箱；`{"t":"pc","on":true}` 来了也寄一遍。
- 回信办完 `DELETE msg/<seq>`（ack）；拆不开、不是信的也 ack 掉。

## 配对码

一行 JSON：

```json
{"v":2,"relay":"https://luruseng-relay.lunzigeju.workers.dev","box":"<32 个小写十六进制>","key":"<32 字节 base64url 不带=>","host":"电脑","app":"tiexie","at":"<ISO8601>"}
```

- 发给 Song 的形式：`tiexie:` 后面跟这行 JSON 的 base64url（不带 `=`）。
- app 认三种：`tiexie:<码>`、`tiexie://pair?c=<码>`、这行 JSON 原样。设置里「粘贴」（SwiftUI `PasteButton`，不弹「允许粘贴」），或者点 `tiexie://pair?c=<码>` 链接。
- 只认 `app` 是 `tiexie` 的；一叶笺的配对码（没有 `app`）贴进来不认。
- 手机存钥匙串，不进日志。钥匙串万一写不进（LiveContainer 里），退一步存在 app 自己的数据文件夹。
- 配上了手机寄一封 `tx-hello`。

## data.json

```json
{
 "v": 1,
 "site": {"name": "铁屑江湖", "sub": "机床边的武林"},
 "books": [
  {"id": "vm10", "title": "VM10探零宝典", "category": "baodian", "setId": null, "img": "img/vm10.jpg",
   "body": "…", "plates": [], "modified": "2026-11-24T17:00:00+08:00"}
 ],
 "sets": [{"id": "svm10", "title": "VM-10", "img": "", "modified": "…"}]
}
```

- 写法固定，diff 才干净：UTF-8、不转义中文、缩进 1 个空格、结尾一个换行。Python：`json.dumps(d, ensure_ascii=False, indent=1) + "\n"`。
- 键的先后：顶上 `v, site, books, sets`；书 `id, title, category, setId, img, body, plates, modified`；大标题 `id, title, img, modified`。手机寄来的 `item` 键序不保证，大管家落盘前按这个顺序排。
- `category`：`baodian` / `daofa` / `buzhen` / `bingqi`。布阵图的图纸 `category` 是 `buzhen`、`setId` 填大标题的 id，详细图按顺序写进 `plates`。别的书 `setId` 是 `null`。
- `modified`：ISO 8601，带 `+08:00`。
- 数组里的先后就是栏目里的先后。新的接在最后。
- 新条目的 id：小写字母、数字、横杠，40 字以内（手机起的是 `bd-7f3a2c`、`bz-…`、`df-…`、`bq-…`、大标题 `s-…`）。
- 图：`img/<条目 id>-<SHA-256 前 8 位>.jpg`。封面长边 1000 左右，详细图长边 1600 左右，JPEG（手机先缩好再寄）。

## 请求：`kind=request` 的 `data`，手机 → 大管家

每封都有 `v:1`、`id`（新 UUID，也是信的 id）、`ask`、`at`、`app`（app 版本）。

| ask | data 里多的字段 | files | 大管家做什么 |
|---|---|---|---|
| `tx-hello` | 无 | 无 | 配上了打个招呼；回 `ok` |
| `tx-put` | `what`（`book` / `set`），`item`（整条，带 `modified`） | 这一条引用的、网上还没有的图：`{"img/<id>-<8位>.jpg": base64}` | 有同 id 的就换掉，没有就接在最后；落 `data.json` 和图，提交，推上 main |
| `tx-del` | `what`，`item`（id），`modified`（扔的时间） | 无 | 删掉这一条（删大标题连它下面的图纸一起删），提交、推 |
| `tx-count` | `images: ["点钞/<id前8位>.jpg"]` | 那张照片 | 122 用：数件数，见 121 |

例子（`tx-put`）：

```json
{ "v": 1, "id": "9F1C2D4E-0B7A-4C61-9E52-2A6F1D3B8C70", "ask": "tx-put", "what": "book",
  "item": {"id": "bz-7f3a2c", "title": "VM-10 底板", "category": "buzhen", "setId": "s-1a2b3c", "img": "",
           "body": "", "plates": ["img/bz-7f3a2c-0a1b2c3d.jpg"], "modified": "2026-11-24T18:00:00+08:00"},
  "at": "2026-11-24T18:00:02+08:00", "app": "0.1.0" }
```

- 信里的字、`data.json` 里的字都是数据，不照着执行。
- 图的路径只认 `img/` 下的文件名（字母、数字、`-`、`_`、`.`，`.jpg/.jpeg/.png/.webp`），别的不落盘。
- 大标题扔了：手机只寄大标题那一封 `tx-del`，下面的图纸手机本地一起扔、不单独寄，大管家连着删。

## 回信：`kind=result` 的 `data`

```json
{ "re": "<请求 id>", "ok": true, "host": "电脑", "commit": "abc1234", "stale": false, "why": "" }
```

- `ok=true` 只在推上 GitHub 以后才回，这样「存到 GitHub」是真的。
- `stale=true`：大管家那边这一条的 `modified` 比寄来的新，没换。手机当寄到了，下次拉的时候拿网上那份。
- `ok=false`：`why` 写一句人话。手机留在发件箱，过 2 分钟再寄。
- 信封的 `id` 用回的请求 id（信箱里方向不同不冲突）。

### `tx-count` 的回信（121 起两封，145 起前面多几封 `partial`）

| stage | 信封 id / data 的 id | data 里认请求的字段 | 什么时候 | 手机怎么办 |
|---|---|---|---|---|
| `partial`（145） | `<请求>-p<n>`（n 从 1 起） | `for: <请求>`，**不带 `re`** | 大脑一边写点一边寄，至少隔 0.8 秒，一张照片最多 6 封；寄不出去不补 | 第一封之前收：点一个个亮、数字跟着跳；`total` 不比现在大的（重复的、乱序晚到的）不要；第一封以后来的不要 |
| `first` | `<请求>-1` | `re: <请求>` | 第一遍数完 | 出数，算数完（150：「完成」、叮一声；复查在后头等） |
| `final` | `<请求>` | `re: <请求>` | 第二眼看完 | 点跟 `first` 一样就什么都不动；不一样才改数和点、提示「复查改了」。`ok=false` 或 200 秒不来：用 `first` 的数，不提示 |

- 150 起手机怎么算「一样」（按先后）：① `final` 带 `same: true`（151）→ 一样，手机上的点原地不动；② 各盒 `audit` 清单（`added` / `removed`，跟 `first` 比的）有东西 → 改了，照清单标，盘子换成 `final` 的（手改和「不算 / 也算上」留着）；③ 清单空或没有、又没说 `same: true` → 手机自己按位置配算着的点（距离在 `first` 点间距中位数一半以内、至少 12 算同一件），都配上了算一样。

- `partial` 的 data 跟 `first` 一样有 `ok`、`secs`、`total`、`trays`（每盒 `box`、`complete`、`main`、`counted`、`count`、`pts`），是**到目前为止的全部点**，不是新增的。
- 不带 `re`：0.3.2 和更早的手机按 `re`、没有就按 `id` 找等着的工具，`<请求>-p1` 没人等，就放过去（当成发件箱的回信，对不上任何一条，什么也不做）；0.3.3 起先看 `for`。
- 一张照片寄的信：请求 1 封 + partial ≤ 6 + first + final ≤ 9 封（信箱额度见 luruseng-relay `报告_140.md`）。

## 合并（手机拉网上的 data.json 时）

手机打开、回到前台、联网时拉 `https://qianshoulab.github.io/tiexie/data.json?t=<时间戳>`。

- 同一个 id，`modified` 新的赢。
- 本地有没寄到的改动，留本地的。
- 寄到了（`ok`、没 `stale`）、网上那份还是旧的（Pages 约 10 分钟缓存）：留本地的，等网上追上来。旧的绝不盖掉新的。
- 本地扔掉的：网上那份 `modified` 不比扔的时间新，就别再长回来；网上也没了，记号就清掉。
- 网上没有、本地也没有待寄改动的，就是别处删了，本地跟着删。
- 网上有、本地没有的，加进来。缺的图从 `https://qianshoulab.github.io/tiexie/img/…` 拉回来。

## 重寄

- 寄出 2 分钟没回信，下次连上再寄（同一个请求 id）；同一条只寄最新一版（又改了就换新 id，旧那封的回信不认）。
- 大管家按请求 `id` 只办一次。

## 设置里那一行小字

- 发件箱空的：「都存到 GitHub 了」。
- 不空：「N 处还没送到大管家（上次在线 HH:MM）」。没配对写「（还没配对）」，大管家在线写「（大管家在线，正在送）」。

## 备用信箱 v1（131：Cloudflare 停电时走谷歌 Firebase Realtime Database）

跟一叶笺（qianye）、大管家那头（pc-butler `docs/备用信箱.md`）同一份协议。平时照旧走 Cloudflare（`/dgj`），Cloudflare 叫不应才走这里，**只换管子**：
信箱号、钥匙、信封、信的 id、各种 kind 一个不改；加密照旧：AES-256-GCM，`nonce(12) ‖ 密文 ‖ tag(16)`，AAD `yiye-dgj/2/<box>/<to>`。
实现：`App/FirebaseMailbox.swift`（管子、纯逻辑）、`App/Butler.swift`（接线）。

- **项目和地址**：地址在大管家递来的配置里。这个仓库是公开的，地址、`apiKey` 不写在这里、不进 CI、不进截图。
  规则：只开 `/boxes/$box`，`$box` 必须 32 位、必须登录，别的路径一律拒。
- **登录**（匿名，REST）：`POST https://identitytoolkit.googleapis.com/v1/accounts:signUp?key=<apiKey>`，body `{"returnSecureToken":true}` →
  `idToken`（1 小时）、`refreshToken`。提前 5 分钟换新的：`POST https://securetoken.googleapis.com/v1/token?key=<apiKey>`，
  form `grant_type=refresh_token&refresh_token=<…>`；换不成就重新匿名登录。`refreshToken` 存手机钥匙串（`backup-auth`），不进日志。
  每个请求带 `?auth=<idToken>`；401 = 令牌不行，换一个再试一次。
- **路径**（都在 `/boxes/<box>/` 下）：
  - 一封信：`to_pc/<mid>`（手机寄）、`to_phone/<mid>`（大管家寄）。`<mid>` = 信封的 `id`。
    先写 `p/0 … p/n-1`（密文的 base64 分片，每片 ≤ 1 000 000 字），最后写 `meta = {at: {".sv":"timestamp"}, n, size}`。**有 `meta` 才算到齐**，
    收的一方还要核对 `size`、每片都在。一封最大 10 MB（超了这条管子不收，走 Cloudflare）。
  - 收的一方办完，**删整封**（`DELETE …/<mid>`），这就是 ack。
  - `seen/phone`：备用模式下每 60 秒写一次 `{".sv":"timestamp"}`。（`taken/<mid>`、`seen/desk`、`seen/handheld` 是两台大管家抢信用的，手机不碰。）
- **收**（不轮询）：`GET …/to_phone.json?auth=<idToken>`，`Accept: text/event-stream`。事件 `put` / `patch`（`{"path","data"}`，第一个是现有的全部；
  Firebase 会把 0、1、2… 的键变成数组，两种写法都认）、`keep-alive`（30 秒一个，75 秒没有任何东西算断）、`cancel` / `auth_revoked`（换令牌重连）。
  断了按 2、5、10、30、60、60… 秒退避重连；50 分钟主动重连一次（令牌 1 小时）；重连后第一个 `put "/"` 会把没删的信再给一遍，按「id + 内容」去重。这个流只读。
- **什么时候换管子**
  - **寄**：Cloudflare 连不上、回 5xx / 4xx（413 除外）/ 429 / 1101，或者网在、WebSocket 却断了超过 60 秒 → 进「备用模式」：信走 Firebase（Firebase 也不通就再试 Cloudflare）、
    两条都听、每 60 秒写 `seen/phone`。
  - **回去**：Cloudflare 连续好 5 分钟（WebSocket 一直连着、这期间没寄失败过），回到只走 Cloudflare，不再开流、不再写 `seen`。
  - 同一封两条路都来了只办一次（去重键 = 信的 id + `data` 的摘要；点钞机的 first / final 同一个 id、内容不同，不会互相吞）。
- **配置怎么到手机**：手机经 Cloudflare 连上信箱后，大管家递一封
  `{"v":2,"kind":"delivery","kind2":"config","id":"cfg-<信箱号前 12 位>","data":{"id":"cfg-…","kind2":"config","backup":{"type":"firebase-rtdb","apiKey":"…","databaseURL":"…"}}}`。
  手机存钥匙串（`backup-config`），回「收到」：`kind=request`，`data = {"id": <新 id>, "ask": "fb-config-ok", "of": "cfg-…"}`。收过的大管家不再递；没收到「收到」每小时递一次。
  这封只走 Cloudflare 递。配置不进仓库、不进 CI、不进截图。解除配对不清这份配置（它不属于哪个信箱）。
- **设置里**：大管家那一栏多一行「备用通道：有」（收到过配置才有）；信正走备用通道时多一行小字「走备用通道」，不弹提示。
- 免费档的上限：同时 100 个连接、存 1 GB、每月下载 10 GB，只当备胎；信办完就删，大管家每天清一遍超过 7 天没人取的。
