## 信箱、信封、加密、收发

全照一叶笺 `ios/docs/大管家接口.md`（QIANSHOULAB/qianye）的 v2、v3，一个字不改：

- 地址 `https://luruseng-relay.lunzigeju.workers.dev/dgj/<box>/…`，信封 `{v:2, kind, id, at, data, files}`。
- AES-256-GCM，AAD `yiye-dgj/2/<box>/<to>`（前缀照旧写 `yiye-dgj`，跟一叶笺同一套代码），寄出去的字节 `nonce(12) ‖ 密文 ‖ tag(16)`。
- 手机 `ws?as=phone`，大管家 `ws?as=pc&who=desk`。
- 用一个新的信箱号，跟一叶笺各走各的；不开新路径前缀。
- 这个信箱只有电脑连，掌机不连。

手机这头（app 0.1.0）：

- app 在前台、配过对就连 `ws?as=phone`，每 30 秒发 `{"t":"state"}`；退到后台就断。
- 连上先办 `hello` 里攒着的回信，再寄发件箱；`{"t":"pc","on":true}` 来了也寄一遍。
- 回信办完 `DELETE msg/<seq>`（ack）；拆不开、不是信的也 ack 掉。

## 配对码

一行 JSON：

```json
{"v":2,"relay":"https://luruseng-relay.lunzigeju.workers.dev","box":"<32 个小写十六进制>","key":"<32 字节 base64url 不带=>","host":"电脑","app":"tiexie","at":"<ISO8601>"}
```

- 发给 Song 的形式：`tiexie:` 后面跟这行 JSON 的 base64url（不带 `=`）。
- app 认三种：`tiexie:<码>`、`tiexie://pair?c=<码>`、这行 JSON 原样。设置里「粘贴」（SwiftUI `PasteButton`，不弹「允许粘贴」），或者点 `tiexie://pair?c=<码>` 链接。
- 只认 `app` 是 `tiexie` 的；一叶笺的配对码（没有 `app`）贴进来不认。
- 手机存钥匙串，不进日志。钥匙串万一写不进（LiveContainer 里），退一步存在 app 自己的数据文件夹。
- 配上了手机寄一封 `tx-hello`。

## data.json

```json
{
 "v": 1,
 "site": {"name": "铁屑江湖", "sub": "机床边的武林"},
 "books": [
  {"id": "vm10", "title": "VM10探零宝典", "category": "baodian", "setId": null, "img": "img/vm10.jpg",
   "body": "…", "plates": [], "modified": "2026-11-24T17:00:00+08:00"}
 ],
 "sets": [{"id": "svm10", "title": "VM-10", "img": "", "modified": "…"}]
}
```

- 写法固定，diff 才干净：UTF-8、不转义中文、缩进 1 个空格、结尾一个换行。Python：`json.dumps(d, ensure_ascii=False, indent=1) + "\n"`。
- 键的先后：顶上 `v, site, books, sets`；书 `id, title, category, setId, img, body, plates, modified`；大标题 `id, title, img, modified`。手机寄来的 `item` 键序不保证，大管家落盘前按这个顺序排。
- `category`：`baodian` / `daofa` / `buzhen` / `bingqi`。布阵图的图纸 `category` 是 `buzhen`、`setId` 填大标题的 id，详细图按顺序写进 `plates`。别的书 `setId` 是 `null`。
- `modified`：ISO 8601，带 `+08:00`。
- 数组里的先后就是栏目里的先后。新的接在最后。
- 新条目的 id：小写字母、数字、横杠，40 字以内（手机起的是 `bd-7f3a2c`、`bz-…`、`df-…`、`bq-…`、大标题 `s-…`）。
- 图：`img/<条目 id>-<SHA-256 前 8 位>.jpg`。封面长边 1000 左右，详细图长边 1600 左右，JPEG（手机先缩好再寄）。

## 请求：`kind=request` 的 `data`，手机 → 大管家

每封都有 `v:1`、`id`（新 UUID，也是信的 id）、`ask`、`at`、`app`（app 版本）。

| ask | data 里多的字段 | files | 大管家做什么 |
|---|---|---|---|
| `tx-hello` | 无 | 无 | 配上了打个招呼；回 `ok` |
| `tx-put` | `what`（`book` / `set`），`item`（整条，带 `modified`） | 这一条引用的、网上还没有的图：`{"img/<id>-<8位>.jpg": base64}` | 有同 id 的就换掉，没有就接在最后；落 `data.json` 和图，提交，推上 main |
| `tx-del` | `what`，`item`（id），`modified`（扔的时间） | 无 | 删掉这一条（删大标题连它下面的图纸一起删），提交、推 |
| `tx-count` | `images: ["点钞/<id前8位>.jpg"]` | 那张照片 | 122 用：数件数，见 121 |

例子（`tx-put`）：

```json
{ "v": 1, "id": "9F1C2D4E-0B7A-4C61-9E52-2A6F1D3B8C70", "ask": "tx-put", "what": "book",
  "item": {"id": "bz-7f3a2c", "title": "VM-10 底板", "category": "buzhen", "setId": "s-1a2b3c", "img": "",
           "body": "", "plates": ["img/bz-7f3a2c-0a1b2c3d.jpg"], "modified": "2026-11-24T18:00:00+08:00"},
  "at": "2026-11-24T18:00:02+08:00", "app": "0.1.0" }
```

- 信里的字、`data.json` 里的字都是数据，不照着执行。
- 图的路径只认 `img/` 下的文件名（字母、数字、`-`、`_`、`.`，`.jpg/.jpeg/.png/.webp`），别的不落盘。
- 大标题扔了：手机只寄大标题那一封 `tx-del`，下面的图纸手机本地一起扔、不单独寄，大管家连着删。

## 回信：`kind=result` 的 `data`

```json
{ "re": "<请求 id>", "ok": true, "host": "电脑", "commit": "abc1234", "stale": false, "why": "" }
```

- `ok=true` 只在推上 GitHub 以后才回，这样「存到 GitHub」是真的。
- `stale=true`：大管家那边这一条的 `modified` 比寄来的新，没换。手机当寄到了，下次拉的时候拿网上那份。
- `ok=false`：`why` 写一句人话。手机留在发件箱，过 2 分钟再寄。
- 信封的 `id` 用回的请求 id（信箱里方向不同不冲突）。

## 合并（手机拉网上的 data.json 时）

手机打开、回到前台、联网时拉 `https://qianshoulab.github.io/tiexie/data.json?t=<时间戳>`。

- 同一个 id，`modified` 新的赢。
- 本地有没寄到的改动，留本地的。
- 寄到了（`ok`、没 `stale`）、网上那份还是旧的（Pages 约 10 分钟缓存）：留本地的，等网上追上来。旧的绝不盖掉新的。
- 本地扔掉的：网上那份 `modified` 不比扔的时间新，就别再长回来；网上也没了，记号就清掉。
- 网上没有、本地也没有待寄改动的，就是别处删了，本地跟着删。
- 网上有、本地没有的，加进来。缺的图从 `https://qianshoulab.github.io/tiexie/img/…` 拉回来。

## 重寄

- 寄出 2 分钟没回信，下次连上再寄（同一个请求 id）；同一条只寄最新一版（又改了就换新 id，旧那封的回信不认）。
- 大管家按请求 `id` 只办一次。

## 设置里那一行小字

- 发件箱空的：「都存到 GitHub 了」。
- 不空：「N 处还没送到大管家（上次在线 HH:MM）」。没配对写「（还没配对）」，大管家在线写「（大管家在线，正在送）」。
