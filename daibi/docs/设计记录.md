# 代笔僧 · 设计记录（给以后接手的 Claude）

代笔僧 = 千手院的自动填表插件：Excel/CSV 一行一行填进别人家网站的表单。对标 Bardeen、Axiom.ai。
介绍页 https://qianshoulab.github.io/daibi/ ，插件包 `daibi/dist/daibi-0.1.0.zip`。

## 结构

```
daibi/
  index.html            介绍页（GitHub Pages）
  img/                  介绍页用的真截图（e2e 跑出来再拼的）
  dist/daibi-0.1.0.zip  打好的插件包（extension/ 原样打包）
  extension/            插件源码，Manifest V3，Chrome/Edge 通用
    manifest.json       权限：sidePanel storage scripting activeTab；网站权限是 optional，按网站临时问
    background.js       只做一件事：点图标打开侧栏
    panel.html/css/js   侧栏 = 大脑：读表、对字段、按行填、跟踪提交、标状态（引擎在 panel.js）
    content.js          网页里的手：scan/fill/submit/values/pick/flash，按需注入，不常驻
    match.js            表头↔字段自动配对（同义词组 + 包含 + 二元组相似度 + 拿样本值验）
    strings.js          代笔僧全部界面文字（以后加英文照抄一份 add('en',…)）
    lib/                ← 通用部分，化缘僧/巡山僧以后并底子用，不含代笔僧业务
      table.js          读写表格：CSV（自动认 UTF-8/GBK/UTF-16、分隔符）、XLSX（自己解 zip，用 DecompressionStream，无第三方库），写 CSV
      page.js           读页面：列字段（单选/复选按 name 成组）、找 label、生成选择器、点选元素、高亮、认验证码
      i18n.js           文案机制：add / t / apply(data-t)
      store.js          chrome.storage.local 封装 + 设置项 schema 渲染（设置页）
      ui.css            颜色 token（跟随浅/深色）、卡片、按钮、开关、设置行、页脚
  test/
    site.js             本地测试站，一个进程 4 个端口 = 4 个网站：订单单页 / 两页向导+成功页 / Ajax 不跳页 / 验证码
    gen.py              生成 20 行测试表（xlsx 真日期单元格、GBK CSV、坏一行的小表、expected.json）
```

## 填表引擎（panel.js）

- 每个网站（origin）一份对应：`maps[origin] = {b:{表头:{sel,label,kind,conf}}, btn, start}`，存 `daibi:maps`；表和每行状态存 `daibi:sheet`。
- 一行的生命周期：`startRow` → `fillStep`（填当前页上还没碰过的已绑字段，记进 `run.seen`）→ 手动模式等用户点提交 / 自动模式 `submitNow` → 
  - 页面跳了（tabs.onUpdated complete）→ `onPage`：页上有没碰过的绑定字段 = 多页表单下一页，接着填；没有 = 这行交了 → `rowDone`。
  - 页面没跳（Ajax）→ `checkAfter` 轮询：已填的文本框一半以上清空 = 交了。
  - 表单回来了但值还在 = 没交上 → 标出错（原因取 validationMessage）。
- `rowDone`：页上又是空表单 → 直接填下一行（手动模式也填，用户只管点提交）；是成功页 → 自动模式跳回 `start` 网址，手动模式主按钮变「回表单，填第 N 行」。
- 多页表单第 2 页的字段，在跑的时候自动补对应（只收 score≥0.75 的），见 `addNewMatches`。
- 出错：自动模式标红后跳回表单页接着下一行；手动模式停下。「重试出错的」把出错行改回待填重跑。
- 验证码（recaptcha/hcaptcha/turnstile/geetest/名字带 captcha/验证码 的框）：填完不提交，标「卡在验证码」，等人自己点提交后继续。

## 权限设计

- 装的时候不要任何网站权限（商店审核友好）。点工具栏图标打开侧栏会给 activeTab。
- 第一次在某网站点「对字段」/「点选」/「填」，在点击里同步调 `chrome.permissions.request({origins:['https://域名/*']})`，用户允许一次，以后这个网站跨页、刷新都能用。
- 匹配模式不能带端口：`http://127.0.0.1/*` 覆盖所有端口（setUrl 里生成 tab.pat）。

## 怎么测

```
cd daibi/test && python3 gen.py            # 生成测试表（已提交，一般不用重跑）
cd ../.. && xvfb-run -a node daibi/test/e2e.js   # 约 2 分钟；SHOTS=目录 指定截图输出
```
- 测试用插件副本，manifest 额外加 `host_permissions: ["http://127.0.0.1/*"]`，省掉授权弹窗（这一步真用户要点「允许」，自动化点不了）。
- 侧栏在测试里当普通标签页开：`panel.html?tab=<目标标签页 id>`（FIXED_TAB），真用户走 side panel。
- 截图拼图脚本没进仓库：把 e2e 出的网页截图和侧栏截图并排放进一个假窗口框再截，出 img/hero.jpg、img/run.jpg。

0.1.0 实测（Chromium，本地站）：订单单页 20 行自动提交 9.4–9.6 秒；两页向导 20 份 21 秒；Ajax 20 条 15 秒；全部逐格核对 0 错；控制台 0 报错。

## 踩过的坑

- Playwright 的 `setInputFiles(路径)` 碰到中文文件名，node 进程直接静默退出、不报错。改传 `{name, mimeType, buffer}`。
- 装了扩展的 Chromium 不能用默认 headless，要 `headless:false` + `xvfb-run`。
- 导航进行中对后台标签页截图会卡 30 秒超时；要截跑动中的画面，先截侧栏、暂停后再截网页。
- 侧栏里 `chrome.permissions.request` 必须在点击处理函数里同步调用，前面不能 await 别的，否则丢了用户手势不弹窗。
- 填值要走原生 value setter + input/change 事件，React/Vue 受控组件才认（测试站的 Ajax 页专门测这个）；最后 `el.blur()`，不然日期框留着焦点高亮。
- 复选/单选用 `el.click()` 真点，网站自己的监听才会触发。
- 结果列表滚到当前行要给 `.rlist` 加 `position:relative`，不然 offsetTop 算错。
- 表头「开发票」对「需要发票」这类说法差太远的，自动配不上，故意留给用户点选，不硬猜。

## 还糙的地方（下一轮）

- iframe 里的表单、Shadow DOM、自定义下拉（div 模拟的 select，如 Element/AntD）都还不认。
- 不能填文件上传框。
- 「自动提交」没有每行间隔设置；对方网站限流时可能要加。
- 多个工作表只取第一个有数据的，可在侧栏切换；没有「从第 N 行开始」之外的筛选。
- 字段对应以 CSS 选择器存，网站改版会失效（会显示「不在这页」，需重新对）。
